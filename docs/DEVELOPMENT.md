# 开发记录

## 2026-05-09：普通实时监控、噪音间隔监控和重点监控名单

本次需求来自一次关键对齐：用户不希望把“间隔监控”扩大到所有普通目录。新的判断是：普通文件夹应当实时监控，只有噪音大、变化频繁但通常净增长不大的目录才降级为间隔快照。重点监控名单则用于临时深入调查可疑目录。

本次实现选择：

- 默认监控对象调整为盘符级入口：`C:\`、`D:\` 和其它用户启用的固定盘。这样产品视角从“几个个人目录”改成“按盘和目录树调查空间变化”。
- 新增 `drive_snapshots`、`tree_snapshots`、`focus_snapshots` 等表。这样盘整体容量、普通目录树快照和重点监控快照不会混在旧的规则快照里，后续 GUI 查询更清晰。
- `file_events` 增加 `source_strategy` 字段，用 `standard` 和 `focus` 区分普通实时事件与重点监控事件。噪音目录默认不写实时事件。
- `scanner.py` 增加盘容量快照、目录树快照、噪音目录快照和重点目录快照。普通目录默认深度 4，重点目录默认深度 8。
- `watcher.py` 增加噪音目录过滤。绝对路径噪音规则按路径排除，`.git`、`node_modules`、`.venv` 这类相对名称规则按路径片段过滤。
- 新增 `focus_log.py`，为重点监控目标生成独立日志目录，便于单独导出给 AI 或人工分析。
- GUI 增加“磁盘”“目录树”“噪音目录”“重点监控”页面。第一版先提供查看和基础编辑能力，复杂的趋势图和暂停/过期控制继续放在后续迭代。

工程取舍说明：

- 没有引入 USN Journal、Sysmon 或 ETW。当前需求的核心是“给出足够分析证据”，不是精确进程归因；继续用 `watchdog` 加快照更适合新手学习和维护。
- 普通目录树不做无限递归，默认 4 层。这样能覆盖大多数“哪个大目录在变大”的调查场景，同时避免一上来遍历整盘所有深层目录导致性能和权限问题。
- 重点监控允许更深，默认 8 层，但必须由用户手动添加。这符合“遇到可疑目录再深入”的调查流程。
- Disk History 自己的数据目录、系统元数据和虚拟内存文件仍然强制排除。这不是隐私策略，而是为了避免死循环和不可可靠访问路径。

验证范围：

- 普通目录会建立实时监听目标。
- 噪音目录不会建立实时监听目标，且相对名称噪音目录的事件会被忽略。
- 普通目录树快照遵守深度限制。
- 噪音目录生成 `noise_snapshot_only` 策略快照。
- 重点监控生成更深层快照和独立日志。
- 新增数据库表可以写入和读取。
- GUI 可以保存噪音目录规则和重点监控目标。

实际验证结果：

- `python -m pytest`：全部测试通过。
- `python -m ruff check .`：代码检查通过。

## 2026-05-09：后期自适应监控策略备忘

本次只更新方案，不实现代码。原因是自适应判断必须依赖一段时间的真实运行数据，如果在早期就强行实现，容易因为样本不足把普通目录误判为噪音目录。

需求背景：

- 用户希望长期运行后，工具可以识别一类目录：它们文件变化很频繁，但磁盘占用并不会短时间内大量增长，只是在一个小范围内来回波动。
- 对这类目录继续保存大量实时事件价值不高，反而会增加数据库体积和 GUI 噪音。
- 更合理的做法是把它们建议设置为间隔扫描，甚至根据稳定程度动态调整扫描间隔。

暂定算法设计：

1. 每个目录维护一个滑动观察窗口，例如最近 72 小时。
2. 从 `file_events` 统计事件数量，从 `tree_snapshots` 统计大小变化。
3. 计算净增长、总波动量、峰谷差、最大单次增长和稳定比例。
4. 满足“事件多、净增长小、峰谷差小、没有增长提醒”的目录进入候选名单。
5. 候选目录继续观察一个冷却期。冷却期内仍然稳定，才在 GUI 中建议降级为间隔扫描。
6. 如果用户接受建议，才写入 `noise_rules` 或动态扫描配置；默认不静默改变用户监控策略。
7. 一旦目录出现快速增长、峰谷差突破或用户加入重点监控名单，立即撤销降级建议。

关键变量：

- 观察窗口：决定用多久的历史判断稳定性。
- 最小事件数：避免低活跃目录被误判。
- 最大净增长：判断是否真的没有占用明显变大。
- 峰谷差上限：判断是否只在小范围内波动。
- 最大单次增长：防止某次大增长被平均值掩盖。
- 稳定比例：用净增长和总波动量的比值衡量“只是来回变化”。
- 冷却时间：防止刚出现短期稳定就自动降级。
- 动态间隔上下限：避免间隔过短没有意义，也避免间隔过长错过重要变化。

实现边界：

- 第一版应只给建议，不自动修改。
- 重点监控名单不参与自动降级。
- 快速增长提醒优先级高于自适应降级。
- GUI 必须解释建议原因，让用户看到具体指标，而不是只显示“系统认为这是噪音目录”。

这个文件用尽量直白的中文记录项目决策和开发过程，方便没有开发基础的用户事后复盘。

## 2026-05-06：GUI 实时监听控制

本次继续推进 0.1 的核心可用性：让 GUI 不只支持手动扫描，还可以启动和停止实时文件变化监听。

实现选择：

- 新增 `DiskHistoryWatcher` 控制器，负责启动、停止和保存当前监听目标。这样 GUI 不需要直接操作 `watchdog.Observer` 的底层细节。
- 新增 `watch_targets()`，只监听“已启用且真实存在”的目录。不存在的默认路径会被跳过，避免启动时因为某个用户没有对应目录而失败。
- GUI 首页增加“开始实时监听”和“停止实时监听”按钮，并显示当前监听状态。
- GUI 使用 `QTimer` 每 3 秒刷新一次图表和表格。后台文件事件只负责写数据库，不直接操作界面，避免跨线程更新 UI。
- SQLite 连接增加线程锁，并允许跨线程使用。原因是 `watchdog` 的事件回调在后台线程执行，而 GUI 在主线程读取数据库。

开发流程说明：

- 先处理数据库线程安全，再接 GUI 按钮。实时监听最容易出问题的地方不是按钮，而是后台线程写入和界面读取同时发生。
- 再抽出监听控制器，避免 CLI 和 GUI 各自写一套监听逻辑。
- 最后补测试，覆盖监听目标筛选、监听器启动/停止、后台线程写数据库。

验证范围：

- `watch_targets()` 只返回存在且启用的目录。
- `DiskHistoryWatcher` 可以启动和停止。
- 数据库可以从后台线程写入事件。
- GUI 可以离屏初始化并关闭。

实际验证结果：

- `python -m pytest`：19 个测试通过。
- `python -m ruff check .`：代码检查通过。
- 离屏创建 `MainWindow`：窗口可以初始化，标题为 `Disk History`。
- 临时目录实时监听检查：启动监听后创建文件，临时 SQLite 数据库成功收到 1 条事件。

## 2026-05-08：产品重定位为磁盘空间变化调查工具

本次需求来自对真实使用场景的重新梳理：用户并不需要软件自动判断“最终原因”，而是在发现磁盘突然少了几个 GB 时，需要足够可靠的记录来帮助自己分析。

因此产品定位从“文件变化审计器 / 清理建议工具”调整为“磁盘空间变化调查工具”。

本次产品决策：

- 目录快照是主要证据，因为用户最关心的是“哪个目录在某段时间内变大了多少”。
- 文件事件是辅助线索，因为实时监听可能漏事件，也不一定能代表最终空间变化。
- 删除清理建议功能，避免项目偏离“调查线索”这个核心目标。
- 不引入 USN Journal、Sysmon 或 ETW。它们可以作为未来增强，但当前阶段会增加复杂度，不符合新手可维护性。
- 增加后台记录模式和当前用户登录后自动启动选项，让工具能持续积累快照历史。

实现选择：

- 新增 `docs/PRODUCT_REQUIREMENTS.md`，把产品定位、核心场景、非目标写清楚。
- 从 GUI 中删除“清理建议”页签，并删除清理建议分析函数和翻译文本。
- 在 `analytics.py` 增加快照对比能力，生成最近 30 分钟、2 小时、今天、7 天的调查窗口。
- GUI 增加“调查”页，把目录净变化作为主证据，同时展示最近 2 小时的文件事件作为辅助线索。
- 新增 `background.py`，后台运行时按配置间隔记录目录快照，并启动实时监听。
- 新增 `startup.py`，通过当前用户启动文件夹创建快捷方式，不写系统服务，不要求管理员权限。
- `settings.json` 增加 `start_on_login` 和 `background_snapshot_interval_minutes`，默认分别为 `false` 和 `10`。

开发流程说明：

- 先删除偏离目标的清理功能，再实现新的调查视图，避免旧功能继续影响界面和文档。

- 设置默认不开机启动，后台快照间隔默认 10 分钟。
- 当前用户启动项路径生成正确。
- 清理建议相关代码和文档描述被移除。

产品决策：

- 日志使用 Markdown + JSONL。`summary.md` 适合人和 AI 直接阅读，JSONL 适合程序逐行处理，也方便后续导入其它分析工具。
- 日志按日期分目录保存，避免单个日志文件无限增长，也方便用户按“哪一天出问题”提取资料。
- 增长提醒只记录事实：某个时间窗口内监控目录净增长超过阈值。它不自动判断原因，继续保持“提供证据，不替用户下结论”的定位。
- 日志目录必须永远排除在扫描和监听之外。否则工具写日志会导致自己记录日志变化，再写更多日志，形成循环。
- 通知栏提醒作为辅助体验，失败不影响核心记录。日志写入才是可靠结果。

实现选择：

- 新增 `activity_log.py`，集中负责 `summary.md`、`snapshots.jsonl`、`events.jsonl`、`alerts.jsonl` 的写入。
- 新增 `paths.py`，提供路径包含关系判断，让扫描器和监听器复用同一套“排除目录”逻辑。
- 新增 `notifications.py`，用 PySide6 自带 `QSystemTrayIcon` 发出增长提醒，不引入额外通知依赖。
- `settings.json` 增加 `log_directory`、`enable_growth_alerts`、`alert_window_minutes`、`alert_growth_threshold_mb`。
- `scanner.py` 在统计目录大小时跳过日志目录。
- `watcher.py` 在建立监听目标和处理文件事件时跳过日志目录。
- `background.py` 每次快照后写入日志，并检测是否超过增长阈值。
