# 开发记录

这个文件用尽量直白的中文记录项目决策和开发过程，方便没有开发基础的用户事后复盘。

## 2026-05-06：环境准备

已安装或确认可用的工具：

- Git for Windows 2.54.0
- Python 3.12.10
- GitHub CLI 2.92.0
- `winget` 已存在，并用于安装官方软件包

选择理由：

- Git 用于版本控制和上传 GitHub。
- Python 3.12 稳定、较新，也适合新手学习。
- GitHub CLI 方便创建仓库、认证和推送代码，但 GitHub 同步不能阻塞本地开发。
- 第一版先用 Python，不直接上 C++，可以降低挫败感，也方便快速验证产品逻辑。

## 自动技术决策

项目默认采用稳健、适合新手理解的方案。除非未来需求明确要求改变，否则不为了炫技增加复杂度。

- 桌面界面：PySide6。它能做真正的 Windows 桌面应用，同时不需要先理解 Web 服务。
- 文件监听：`watchdog`。它比 NTFS USN Journal 更容易理解，足够支撑第一版。
- 数据库：Python 标准库里的 `sqlite3`。本地、简单、不需要额外数据库服务。
- 打包方向：后续使用 PyInstaller。等源码运行稳定后再做安装包。
- 隐私默认策略：监控和隐私规则可配置，敏感目录默认使用汇总记录。
- GitHub 安全策略：从第一次提交开始就忽略数据库、日志、导出文件和本地配置。

## 第一版实现范围

第一版本地版本包含：

- 使用通用路径模板的默认监控规则，不写死个人绝对路径。
- 自动生成本地 `settings.json`，让监控规则和隐私规则可以配置。
- 本地应用数据目录解析。
- SQLite 表结构和读写方法。
- 目录快照扫描。
- 基础文件事件处理。
- 包含总览、时间线、监控规则、隐私、数据管理的桌面界面。
- 覆盖路径展开、隐私规则、数据库写入和目录扫描的测试。

- NTFS USN Journal 集成。

这些功能先延后处理。对新手友好的第一版应该先做到结构清楚、可以运行、可以测试，再逐步加入底层 Windows 能力。

## 2026-05-06：GUI 可视化、双语界面与新手文档改进

本次需求：

- 本次改动和选择理由继续记录在文档里。

实现选择：

- 新增 `analytics.py`，把“如何从数据库算出图表数据”从 GUI 里拆出来。这样界面代码不承担业务计算，后续也更容易写测试。
- 新增 `i18n.py`，集中管理中英文界面文本。这样以后修改文案或补语言时，不需要在窗口代码里到处找字符串。

- 图表使用 PySide6 自带 QtCharts。理由是项目已经使用 PySide6，继续用同一套生态能减少依赖和学习成本。

本次新增的可视化：

## 2026-05-06：GUI 实时监听控制

本次继续推进 0.1 的核心可用性：让 GUI 不只支持手动扫描，还可以启动和停止实时文件变化监听。

实现选择：

- 新增 `DiskHistoryWatcher` 控制器，负责启动、停止和保存当前监听目标。这样 GUI 不需要直接操作 `watchdog.Observer` 的底层细节。
- 新增 `watch_targets()`，只监听“已启用且真实存在”的目录。不存在的默认路径会被跳过，避免启动时因为某个用户没有对应目录而失败。
- GUI 首页增加“开始实时监听”和“停止实时监听”按钮，并显示当前监听状态。
- GUI 使用 `QTimer` 每 3 秒刷新一次图表和表格。后台文件事件只负责写数据库，不直接操作界面，避免跨线程更新 UI。
- SQLite 连接增加线程锁，并允许跨线程使用。原因是 `watchdog` 的事件回调在后台线程执行，而 GUI 在主线程读取数据库。

开发流程说明：

- 先处理数据库线程安全，再接 GUI 按钮。实时监听最容易出问题的地方不是按钮，而是后台线程写入和界面读取同时发生。
- 再抽出监听控制器，避免 CLI 和 GUI 各自写一套监听逻辑。
- 最后补测试，覆盖监听目标筛选、监听器启动/停止、后台线程写数据库。

验证范围：

- `watch_targets()` 只返回存在且启用的目录。
- `DiskHistoryWatcher` 可以启动和停止。
- 数据库可以从后台线程写入事件。
- GUI 可以离屏初始化并关闭。

实际验证结果：

- `python -m pytest`：19 个测试通过。
- `python -m ruff check .`：代码检查通过。
- 离屏创建 `MainWindow`：窗口可以初始化，标题为 `Disk History`。
- 临时目录实时监听检查：启动监听后创建文件，临时 SQLite 数据库成功收到 1 条事件。

## 2026-05-08：产品重定位为磁盘空间变化调查工具

本次需求来自对真实使用场景的重新梳理：用户并不需要软件自动判断“最终原因”，而是在发现磁盘突然少了几个 GB 时，需要足够可靠的记录来帮助自己分析。

因此产品定位从“文件变化审计器 / 清理建议工具”调整为“磁盘空间变化调查工具”。

本次产品决策：

- 目录快照是主要证据，因为用户最关心的是“哪个目录在某段时间内变大了多少”。
- 文件事件是辅助线索，因为实时监听可能漏事件，也不一定能代表最终空间变化。
- 删除清理建议功能，避免项目偏离“调查线索”这个核心目标。
- 不引入 USN Journal、Sysmon 或 ETW。它们可以作为未来增强，但当前阶段会增加复杂度，不符合新手可维护性。
- 增加后台记录模式和当前用户登录后自动启动选项，让工具能持续积累快照历史。

实现选择：

- 新增 `docs/PRODUCT_REQUIREMENTS.md`，把产品定位、核心场景、非目标写清楚。
- 从 GUI 中删除“清理建议”页签，并删除清理建议分析函数和翻译文本。
- 在 `analytics.py` 增加快照对比能力，生成最近 30 分钟、2 小时、今天、7 天的调查窗口。
- GUI 增加“调查”页，把目录净变化作为主证据，同时展示最近 2 小时的文件事件作为辅助线索。
- 新增 `background.py`，后台运行时按配置间隔记录目录快照，并启动实时监听。
- 新增 `startup.py`，通过当前用户启动文件夹创建快捷方式，不写系统服务，不要求管理员权限。
- `settings.json` 增加 `start_on_login` 和 `background_snapshot_interval_minutes`，默认分别为 `false` 和 `10`。

开发流程说明：

- 先删除偏离目标的清理功能，再实现新的调查视图，避免旧功能继续影响界面和文档。
- 快照对比不改变数据库表结构，复用已有 `directory_snapshots`，降低迁移风险。
- 开机启动默认关闭，因为它会让程序长期后台运行，必须由用户明确开启。

验证范围：

- 快照对比能正确计算增长和减少。
- 快照不足时调查窗口显示“无法对比”的空状态。
- 设置默认不开机启动，后台快照间隔默认 10 分钟。
- 当前用户启动项路径生成正确。
- 清理建议相关代码和文档描述被移除。

实际验证结果：

- `python -m pytest`：25 个测试通过。
- `python -m ruff check .`：代码检查通过。
- `python -m disk_history scan`：扫描命令运行成功，并写入本地 SQLite 数据库。
- `python -m disk_history --help`：已包含 `background` 子命令。
- 离屏创建 `MainWindow`：页签为“概览、时间线、调查、来源占比、活动热力图、设置”，不再包含清理页。

补充说明：

- 这次扫描会更新 `%LOCALAPPDATA%\DiskHistory\disk_history.sqlite3`，它是本地运行数据，不在 Git 仓库里。
- 开机启动功能只在用户点击设置页按钮后创建当前用户启动项；测试不会修改真实启动项。
