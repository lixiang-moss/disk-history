# 安全与隐私

Disk History 是个人本地工具，也计划未来开源。因此安全设计的重点是：默认不收集过多信息，不上传数据，不误提交隐私文件。

它是磁盘空间变化调查工具，不是清理工具。

## 工具会记录什么

根据隐私设置，工具可能记录：

- 文件或目录路径元数据。
- 文件大小。
- 变化时间。
- 事件类型，例如新增、修改、删除、移动。
- 目录快照大小。
- 易读的分类名称，例如 Downloads 或 Temp。

## 工具不会记录什么

第一版不会记录：

- 文件内容。
- 文档正文。
- 图片内容。
- 浏览器历史。
- 聊天内容。
- 密码、token、密钥等敏感内容。
- 不会自动删除文件。
- 不会提供清理建议功能。

## 隐私模式

- 详细记录：保存具体路径和大小变化元数据。
- 汇总记录：只保存配置规则名称和汇总大小信息，不保存具体文件名。
- 忽略：完全不记录该路径的事件。

敏感用户目录默认应使用汇总记录。

## 用户配置

应用会创建本地可编辑配置文件：

```text
%LOCALAPPDATA%\DiskHistory\settings.json
```

规则使用 `{USERPROFILE}` 这类路径模板，而不是某个用户电脑上的绝对路径。用户可以在不改源码的情况下调整隐私模式。

GUI 设置页可以编辑监控规则。建议原则是：不确定是否敏感的目录先使用“汇总记录”，确认需要具体文件线索时再改成“详细记录”。“忽略”模式适合聊天软件、浏览器用户数据、云盘同步目录等你不希望进入事件记录的位置。

## GitHub 安全规则

绝对不要提交生成的本地数据：

- `*.db`
- `*.sqlite`
- `*.sqlite3`
- `*.db-wal`
- `*.db-shm`
- `logs/`
- `exports/`
- 本地配置文件

这些模式已经写进 `.gitignore`。

## 日志文件安全

可提取日志默认保存在：

```text
%LOCALAPPDATA%\DiskHistory\logs\
```

日志中的 `snapshots.jsonl`、`events.jsonl`、`alerts.jsonl` 和 `summary.md` 可能包含本机路径、目录名称、文件名和大小变化信息。它们是为了方便用户自己分析或复制给 AI 使用，不适合直接上传到公开仓库。

为了避免循环记录，日志目录及其子目录永远不会被扫描或监听。即使用户把日志目录配置成监控目录，工具也会跳过它。

如果你需要把日志交给 AI 分析，建议先快速检查是否包含不希望暴露的路径或文件名。

## 导出报告安全

调查报告导出时默认隐藏常见私人路径，例如 `{USERPROFILE}`、`{LOCALAPPDATA}`、`{APPDATA}`。这能降低直接暴露本机用户名和部分目录结构的风险。

但路径隐藏不是内容脱敏工具。报告仍可能包含规则名称、目录名称、文件名、扩展名和大小变化。公开分享前仍然应该人工检查一次。

## 删除安全

第一版不会删除任何文件，也不提供清理建议功能。这个工具只负责记录和展示调查线索。

## 开机启动安全

开机启动默认关闭。用户开启后，工具只为当前用户创建登录后启动项，不安装系统服务，不要求管理员权限。

开机启动的作用是持续记录目录快照和文件事件元数据。它不会读取文件内容，也不会上传数据。
